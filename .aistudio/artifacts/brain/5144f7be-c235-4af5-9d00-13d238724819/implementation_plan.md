# План внедрения автоматического обхода блокировок (Zero-Config) для Vibegram PRO

## 1. Главная цель
Сделать так, чтобы **любой пользователь** открывал `https://dmitrijai.github.io/Vibegram-PRO/` (или APK) и мессенджер **сразу работал без VPN и без единой настройки**, сохраняя 100% функций (чаты, фото/видео, голосовые, видеокружочки, звонки, сторис, каналы, ИИ-ассистент).

---

## 2. Архитектура невидимого авто-обхода

### А. Внешний прозрачный релей-туннель через наш сервер Google Cloud Run (`server.ts`)
* **Почему раньше не работало на GitHub Pages:** GitHub Pages раздаёт только статику, поэтому встроенный прокси `/api/supabase` там не запускался, а прямые домены `supabase.co` и Cloudflare (`vibegram.qzz.io`) резались ТСПУ РКН.
* **Решение:** Наш сервер в Google Cloud Run (`https://ais-pre-6cxwdfewxdnz4m3mfqzasb-521433209996.europe-west2.run.app/api/supabase`) работает 24/7 на инфраструктуре Google и имеет прямой гигабитный канал до европейского узла Supabase.
* Мы включим на `server.ts` полную поддержку кросс-доменных запросов (**CORS** для `https://dmitrijai.github.io` и мобильных клиентов) и потоковую передачу любых данных (REST, Auth, Storage для фото/аудио/кружочков).

### Б. «Умная гонка» маршрутов (Smart Parallel Race в `src/network.ts`)
* При старте приложения клиент в фоне за миллисекунды проверяет доступность узлов и автоматически пускает трафик через **первый ответивший канал**:
  1. Локальный туннель `/api/supabase` (если открыто напрямую по ссылке Cloud Run).
  2. Удалённый туннель Google Cloud Run (`https://ais-pre-6cxwdfewxdnz4m3mfqzasb-521433209996.europe-west2.run.app/api/supabase`) — работает прямо с GitHub Pages без VPN.
  3. Резервный туннель `https://ais-dev-6cxwdfewxdnz4m3mfqzasb-521433209996.europe-west2.run.app/api/supabase`.
  4. Прямой узел Supabase и резервный воркер (на случай если пользователь с зарубежного интернета).
* Мёртвый домен `vibegram.qd.je` полностью удаляется из кода.

### В. Отключение зависаний `navigator.locks` и фикс ошибки 400 (`src/config.ts`, `src/main.ts`)
* **Проблема из ваших скринов:** Внутренний механизм `@supabase/gotrue-js` блокировал очередь запросов через `navigator.locks` на 5–30 секунд при малейшей сетевой задержке, вызывая каскад ошибок `AbortError: Lock broken by another request with the 'steal' option`.
* **Решение:** Передаём в конфигурацию `supabase` собственный неблокирующий `auth.lock`, который мгновенно выполняет операции без взаимоблокировок вкладок и таймаутов.
* **Фикс 400 ошибки в live-обновлениях:** В `src/main.ts` в обработчике `chats` заменяем `.single()` на безопасный `.maybeSingle()` с предварительной проверкой `if (!state.currentUser?.id) return;`.

## 3. Полная очистка интерфейса от настроек прокси (`src/ui.ts`, `src/main.ts`)
* Полностью убираем кнопку «Сеть и обход РКН» с экрана входа и из бокового меню/настроек.
* Удаляем модальное окно ручного ввода прокси-серверов.
* Пользователь видит только чистый интерфейс мессенджера, а вся маршрутизация и переключение при сбоях происходят под капотом абсолютно незаметно.
